Make disrupted maritime shipping recover faster.

In the Winter Simulation Conference (WSC) 2026 Simulation Challenge, we write four decision hooks inside a simulation supplied by the challenge organizer. The single objective is to minimize Cumulative Resilience Loss without breaking simulation integrity or submission rules.

01 · Context

The challenge in one minute

A maritime network moves container shipments through ports, vessels, repeating service routes and transfers between services. Disruptions close berths or slow sailing legs. Our participant code decides how the system should respond.

1

Run the network

A 140-day warm-up stabilizes the model before scoring. It is followed by 360 measured days under one practice disruption scenario and one fixed random seed.

2

Intervene through four hooks

We may prioritize berths, create temporary routes, assign initial booking chains, or rebook cargo already in transit.

3

Measure transport time

The simulator reports TEU-weighted ATT for each five-day period, so larger shipments influence the result more.

4

Keep only strict improvements

A candidate survives only when its complete 72-period loss is lower than the fixed fallback by more than 0.000000001.

ATT ratio = baseline Average Transport Time ÷ disrupted-scenario Average Transport Time
period loss = (1 − ATT ratio) × inclusive period days
cumulative resilience loss = Σ period loss  →  lower is better

02 · Terms

Plain-language glossary

The domain and experiment vocabulary used throughout this page.

WSC
Winter Simulation Conference, whose 2026 program includes this simulation challenge.
Organizer
The challenge authors who supply the simulation, data, default behavior and official rules.
Participant strategy
Our submitted decision code. It may respond through four predefined functions but may not alter the framework or outputs.
Hook
A predefined function the simulator calls at a decision point, such as choosing a berth or route.
TEU
Twenty-foot Equivalent Unit: the standard measure of container volume. One 40-foot container is usually two TEU.
ATT
Average Transport Time: average cargo travel time from origin to destination, weighted here by shipment TEU.
Cumulative Resilience Loss
The official score: disruption-related ATT loss summed across all measured periods. Lower is better.
Baseline
The undisrupted reference ATT used inside the scoring formula. It is distinct from the fallback strategy result.
Fallback
The organizer’s default response policy, used whenever our hook returns None. It is also our retained solution.
Candidate
One proposed participant strategy tested against the fallback under the same complete run configuration.
None, True, False
None delegates to fallback. In booking assignment, True means assigned and False means retry later.
Berth
A place at a port where one vessel docks to discharge and load cargo.
Leg
One directed sailing connection from a departure port to an arrival port.
Service route
A repeating cycle of sailing legs operated by one or more vessels.
Booking chain
The ordered service-route segments a shipment plans to use from origin to destination.
Transshipment
Moving cargo between vessel services at an intermediate port, adding handling and possible waiting time.
Disruption
A temporary event such as a closed berth or a sailing leg slowed by a multiplier.
Warm-up / measured horizon
Warm-up stabilizes the simulated network. The measured horizon is the later interval used for scoring.
Period
One scoring interval. Round 0 uses 72 consecutive five-day periods over 360 measured days.
Scenario / seed
A scenario defines conditions and disruptions. A random seed fixes simulation randomness for reproducibility.
Round 0 / hidden scenario
Round 0 is visible practice. A hidden scenario is an unseen evaluation case used to discourage overfitting.
No-op adapter
A participant strategy that makes no decisions itself: every hook returns None and uses fallback.
Headway
The time between successive vessels serving the same route or port call.
Smoke test / full run
A smoke test is a short wiring check. A full run completes warm-up plus all measured days and produces an acceptance result.
TDD, RED, GREEN
Test-Driven Development: prove a behavior test fails (RED), then add the minimum code that makes it pass (GREEN).
Preflight / package
Preflight is the complete pre-run safety check. A package is the reproducible compressed archive containing only allowed participant files.
SHA-256
A content fingerprint proving that a file or result is byte-for-byte identical to a fixed reference.
Deterministic / reproducible
The same code, inputs, dependency versions and random seed produce exactly the same result each time.
Current checkout
The exact repository files and dependency versions being used now. Different checkouts can produce different reference results.
Acceptance threshold / strict improvement
The fixed score a candidate must beat. Equality is rejection; the candidate must be lower by more than 0.000000001.
Revert
A version-control operation that undoes a rejected candidate while preserving its implementation and evidence in history.
Utilization
The share of available service capacity actually used to move cargo.
Detour
An alternative path used to avoid a disrupted berth or sailing leg.
Real-context divergence
Proof that a candidate changes at least one actual simulator decision compared with fallback before an expensive full run.

03 · Rules

What must always remain true

Official material wins over this summary. These are the constraints that shape every experiment and submission.

  • Round 0 is practice only. It must never be submitted as an official entry.
  • Lower loss wins. Mean ATT alone cannot accept a candidate.
  • Only response strategies ship. Everything required must live in response_strategies/, the submission folder containing our hooks.
  • Organizer assets stay private. Source, inputs and outputs are ignored and never redistributed.
  • Submission code is self-contained. No internet, external programs, local-file access, environment settings or assumptions about the working folder.
  • Behavior is deterministic. No wall-clock decisions, unseeded randomness or changeable saved state shared between runs.
  • Interfaces are exact. Non-None responses must satisfy organizer validation.
  • Hidden evaluation matters. Later rounds use unseen scenarios and multiple random seeds.

04 · Experiments

What we tried

Every row is one completed full candidate. All were rejected and reverted to the no-op participant adapter: all four hooks return None, delegating each decision to the organizer fallback.

Candidate Core idea Loss Result What it taught us
Age-weighted berth priority Serve vessels carrying the oldest, heaviest cargo first. 22.3199 +22.12% Cargo age overweights old cargo; the marginal cost of delaying one TEU is not age-dependent.
Static transfer-aware routing Charge a fixed 84-hour penalty per booking edge. 30.6355 +67.62% An excellent early screen failed over 360 days. Static transfer penalties miss where each vessel is in its repeating schedule.
Suppress alternative routes Do not create temporary detour services during disruption. 18.6736 Equal The candidate was observably equivalent to fallback for the measured output. Equality is rejection.
Suppress in-transit rebooking Keep carried cargo on its original booking during disruption. 21.6816 +16.11% Reactive rebooking is valuable; suppressing it trapped or delayed cargo enough to worsen the score.
Temporal safe routing Use the nominal path when the disrupted resource would recover before earliest possible arrival. 22.7324 +21.74% Optimistic lower bounds did not capture actual waiting, assignment and service timing.
Smith-rule berth priority Apply Smith’s scheduling rule: prioritize the most affected TEU per predicted berth-service hour. 18.6736 Equal The berth-choice hook made no decision that differed from the organizer fallback in this run.
Safe recovery shuttle Run a temporary shuttle over the largest safe portion of a route when a complete alternative cannot be built. 23.0187 +23.27% The shuttle ran at about 0.30% utilization and displaced more useful capacity.
Recovery hold vs detour Hold cargo at origin when waiting for recovery is predicted faster than the safe detour. 22.1967 +18.87% Model-derived expected time still missed enough operational timing to make origin holding harmful overall.

05 · Lessons

What the evidence says so far

The fallback is strong

Broad overrides have been neutral or materially worse. A useful candidate must target a narrow, evidenced decision.

Geometry is not time

Distance, transfer count and optimistic sailing time miss each vessel’s place in its cycle, time between services, berth queues and cargo handling.

Full-horizon evidence wins

Short screens and plausible theory cannot replace the official 72-period score. The transfer experiment demonstrated this sharply.

Behavioral activity must be proven

Passing tests is insufficient if the hook never changes a real decision. We now prove real-context divergence before running.

One variable at a time

Each candidate fixes one policy, threshold and acceptance rule before execution. No tuning occurs after seeing the result.

Rejection is a clean outcome

Evidence is preserved, candidate changes are reverted, and the exact fixed fallback is restored and reverified.
