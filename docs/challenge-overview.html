Challenge context & experiment log · 7 August 2026

Make disrupted maritime shipping recover faster.

In the Winter Simulation Conference (WSC) 2026 Simulation Challenge, we write four decision hooks inside a simulation supplied by the challenge organizer. The single objective is to minimize Cumulative Resilience Loss without breaking simulation integrity or submission rules. Round 1 has its own private source tree; four controlled Round 1 strategy experiments are recorded below alongside the Round 0 history.

01 · Context

The challenge in one minute

A maritime network moves container shipments through ports, vessels, repeating service routes and transfers between services. Disruptions close berths or slow sailing legs. Our participant code decides how the system should respond.

1

Run the network

Round 0 used a 140-day warm-up followed by 360 measured days. Round 1 has its own private source tree and must be measured separately.

2

Intervene through four hooks

We may prioritize berths, create temporary routes, assign initial booking chains, or rebook cargo already in transit.

3

Measure transport time

The simulator reports TEU-weighted ATT for each five-day period, so larger shipments influence the result more.

4

Keep only strict improvements

A candidate survives only when its complete 72-period loss is lower than the fixed fallback by more than 0.000000001.

ATT ratio = baseline Average Transport Time ÷ disrupted-scenario Average Transport Time
period loss = (1 − ATT ratio) × inclusive period days
cumulative resilience loss = Σ period loss  →  lower is better

02 · Terms

Plain-language glossary

The challenge-specific vocabulary used throughout this page.

WSC
Winter Simulation Conference, whose 2026 program includes this simulation challenge.
Participant strategy
Our submitted decision code. It may respond through four predefined functions but may not alter the framework or outputs.
Hook
A predefined function the simulator calls at a decision point, such as choosing a berth or route.
TEU
Twenty-foot Equivalent Unit: the standard measure of container volume. One 40-foot container is usually two TEU.
ATT
Average Transport Time: average cargo travel time from origin to destination, weighted here by shipment TEU.
Cumulative Resilience Loss
The official score: disruption-related ATT loss summed across all measured periods. Lower is better.
Baseline
The undisrupted reference ATT used inside the scoring formula. It is distinct from the fallback strategy result.
Fallback
The organizer’s default response policy, used whenever our hook returns None. It is also our retained solution.
Berth
A place at a port where one vessel docks to discharge and load cargo.
Leg
One directed sailing connection from a departure port to an arrival port.
Service route
A repeating cycle of sailing legs operated by one or more vessels.
Booking chain
The ordered service-route segments a shipment plans to use from origin to destination.
Transshipment
Moving cargo between vessel services at an intermediate port, adding handling and possible waiting time.
Disruption
A temporary event such as a closed berth or a sailing leg slowed by a multiplier.
Warm-up / measured horizon
Warm-up stabilizes the simulated network. The measured horizon is the later interval used for scoring.
Period
One scoring interval. Round 0 uses 72 consecutive five-day periods over 360 measured days.
Scenario / seed
A scenario defines conditions and disruptions. A random seed fixes simulation randomness for reproducibility.
Round 0 / hidden scenario
Round 0 is visible practice. A hidden scenario is an unseen evaluation case used to discourage overfitting.
No-op adapter
A participant strategy that makes no decisions itself: every hook returns None and uses fallback.
Headway
The time between successive vessels serving the same route or port call.

03 · Rules

What must always remain true

Official material wins over this summary. These are the constraints that shape every experiment and submission.

  • Round 0 is practice only. It must never be submitted as an official entry.
  • Round 1 is official. It closes on 23 August 2026 and carries 20% of the final weighting.
  • Lower loss wins. Mean ATT alone cannot accept a candidate.
  • Only response strategies ship. Everything required must live in response_strategies/, the submission folder containing our hooks.
  • Organizer assets stay private. Source, inputs and outputs are ignored and never redistributed.
  • Submission code is self-contained. No internet, external programs, local-file access, environment settings or assumptions about the working folder.
  • Behavior is deterministic. No wall-clock decisions, unseeded randomness or changeable saved state shared between runs.
  • Interfaces are exact. Non-None responses must satisfy organizer validation.
  • Hidden evaluation matters. Later rounds use unseen scenarios and multiple random seeds.

04 · Experiments

What we tried

Each Round 0 experiment changed one decision rule, then ran the same complete 360-day disruption simulation. We compared its loss with the 18.6736 Round 0 fallback. Round 1 trials used their own complete simulation and 20.4367 Round 1 fallback. Lower is better; equality is not an improvement. All four Round 1 trials were rejected, so the no-op fallback remains active.

Experiment What we tested and why Result
Serve ships with older cargo first When a berth became free and several ships were waiting, we chose the ship carrying the largest amount of cargo that had already been travelling for a long time. We expected this to prevent old, heavily delayed cargo from waiting even longer. Instead, cargo age gave too much priority to some ships and produced worse berth choices overall. 22.3199
19.53% worse
Prefer routes with fewer transfers When choosing a route for new cargo, we added an estimated 84-hour cost for every transfer between services. This made direct routes more attractive because every transfer can add unloading, waiting and reloading time. The fixed estimate ignored when the next vessel would actually arrive, so routes that looked simpler could still be much slower. 30.6355
64.06% worse
Turn off temporary detour routes During an active disruption, we stopped the fallback from creating temporary services around the blocked or slowed part of the network. We suspected those detours might create long loops or reserve ships that could be used more effectively elsewhere. The final transport-time output was identical to fallback, so this change had no measurable effect in this scenario. 18.6736
No change
Stop rerouting cargo already at sea When disruption affected cargo already aboard a ship, we kept its original remaining route instead of letting fallback discharge it early and build a new route. We expected fewer transfers and less handling to avoid unnecessary delay. In practice, fallback’s reactive rerouting was valuable; preventing it left cargo on slower plans. 21.6816
16.11% worse
Use a normal route if recovery seems early enough For each shipment, we estimated the earliest time it could reach the disrupted berth or sailing leg. If the disruption was scheduled to end first, we kept the normal route instead of detouring. The estimate used ideal travel times and missed real queues, vessel schedules and cargo handling, so it declared some routes safe when they were not operationally efficient. 22.7324
21.74% worse
Help the most cargo per berth hour When ships competed for a berth, we divided the affected container volume aboard each ship by its predicted berth-service time. We then preferred the ship that could help the most cargo per hour of scarce berth capacity. In the real simulation this rule never selected a different ship than fallback, so the result could not change. 18.6736
No change
Run a short shuttle around the safe part of a route When no complete route could avoid the disruption, we created a temporary shuttle over the largest connected portion that remained safe. The goal was to keep some cargo moving instead of waiting for the full route to recover. The shuttle used only about 0.30% of its capacity and consumed ships or service capacity that were more useful elsewhere. 23.0187
23.27% worse
Wait at origin instead of taking a detour Before assigning a route, we compared two estimates: wait at the starting port until the disrupted route recovered, or leave immediately on a safe detour. We held the cargo only when waiting appeared faster. The estimate missed enough real vessel and port timing that cargo often waited longer than it would have under fallback. 22.1967
18.87% worse
Let transshipment cargo become ready before serving its receiving ship At a one-berth port, cargo transferred from one service to another can still be completing an internal booking update when its receiving ship starts loading at the same simulated time. We tested serving a carefully chosen buffer ship first only when that short delay was predicted to let enough waiting cargo become ready for the receiving ship. The safeguard worked in focused simulator tests, but it never changed the final transport-time output during the complete Round 0 run. 18.6736
No change

Experiment What we tested and why Result
Defer future-only rebooking For cargo already on a vessel, we kept the current booking when a disruption affected only a later leg or port. We let the organizer fallback re-plan when the vessel's current segment or port was directly affected, so the experiment changed only premature future-only rerouting. 23.3874

Serve a vessel that can progress next During a disruption, we separated waiting vessels whose next leg or destination berth was blocked from vessels that could continue immediately. Only when both groups were present did we keep the fallback ranking but restrict the choice to the progress-capable group. The full 72-period result was byte-identical to the fallback, so the policy made no measurable change. 20.4367
No change; rejected by strict equality gate
Choose initial bookings by predicted disruption time For new cargo during an active disruption, we kept closed ports excluded but allowed slowed sailing legs when a time-dependent route estimate said they would still finish sooner than a detour. The estimate used deployed vessel speed, the active disruption multiplier and recovery time, then installed a complete booking chain only after validating the whole path. It changed many initial choices, but the added disruption-aware routing made the total result worse. 27.0254
